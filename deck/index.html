§ 02 · Positioning
◆
a bazaar, not a publisher

A bench for puzzles — sibling to forge-state.

◆
Nightly cadence

Curiosity is bursty; design is patient. Mark all day, puzzles by morning.

◆
Sealed sandbox

Generated game code never runs in your shell. Docker, deny-egress, no secrets.

◆
Unsolvable is a finding

A puzzle that fails playtest still ships as an honest report. Parallels forge's build-failed.

◆
Playable artifact

Every success ships HTML, PDF, or an ARG pack. A stranger can pick it up tonight.

Local-first. No server. Same single-writer + file-per-entity + two-plane pattern as forge-state — the domain is puzzles, not code.

§ 04 · Two-plane isolation

Trusted secrets here. Untrusted generators there.

Host · control plane
Reasons. Publishes. Holds secrets.
  • ▸ Anthropic · Slack · GitHub · scsiwyg · GHCR keys
  • ▸ orchestrator · harvesters · researcher · designer · reporter · publisher
  • ▸ egress: api.anthropic.com, slack, github, scsiwyg, registries
  • ▸ sops-age secret store, loaded at run start
never executes generated game code
→
source +
design.md
artifact ·
test log
←
Container · data plane
Renders. Solves. No secrets.
  • ▸ fresh container per puzzle · torn down after read
  • ▸ builder · tester · packager run here
  • ▸ egress: package registries only (deny-default)
  • ▸ CPU 4 · mem 8g · per-puzzle timeout 1800s
never sees a host token

The boundary is crossed one way only. Nothing trusted enters the container; nothing untrusted runs on the host.

§ 08 · The sandbox

Disposable. Capped. Per artifact kind.

Container · per puzzle · disposable
Docker, deny-egress, capped.
  • ▸Per artifact_kind base: node:20 · pandoc · headless-chrome · ubuntu:24.04
  • ▸Runs: render artifact · solver pass · packager
  • ▸Egress: package registries only (deny-default; no host secrets)
  • ▸Caps: cpu=4 · mem=8g · per_puzzle_timeout_s=1800
  • ▸Fresh container per puzzle; torn down after results are read.
Bases keyed by artifact_kind
kind
image
html-static
node:20-alpine
pdf
pandoc/latex:3
docker-web
node:20 · python:3.12
breadcrumb-pack
ubuntu:24.04 + zip
solver pass
headless-chrome / python
The tester replays the artifact and tries to solve it. Unsolvable is a real outcome, not an error.

Generated game code never executes in the host shell. Every render and every solver pass happens in a fresh container.
